## 〇、这份文档解决什么

需求说明书定了"做什么"（四入口、纯前端、评分五维），但没有定"长什么样"。
本文档负责**为界面视觉做选型与留痕**：

- 从四个入口中**选定 3 个主题**做风格探索（第 3 节）；
- 每个主题给出 **10 个可对比的设计风格**（第 4–6 节）；
- 全部风格**以独立 HTML 界面原型落地**，配一张**评审墙**便于横向挑选（第 2 节命名规范）。

> ⚠️ 这些原型是**风格探索稿（design spike）**，用来"看效果、做决策"，不是最终工程代码。
> 定稿后，胜出的风格会被翻译进 Vue + Tailwind 正式项目（见需求说明书第六章）。

|---|---|---|

| D-4 | 内容准确、取权威口径（R-08 / C-01~02） | 原型内文案全部取自 `references/01~04`；未公布内容标注「待官方发布」，禁止编造 |

## 二、命名规范与目录结构（★ 防重复的核心）

### 2.1 命名规范

沿用需求说明书 5.4 的入口短名（`01-summit` / `02-nanshan` / `03-pedia` / `04-youth`），加前缀区分用途，全部置于作者命名空间 `qoder/` 之下：

| 对象 | 规范 | 示例 |
|---|---|---|
| 作者命名空间（根目录） | `prototypes/<负责人>/` | `prototypes/qoder/` |
| 主题（入口）目录 | `eNN-<英文短名>/`（e=entry，NN 与需求说明书入口编号对齐） | `e02-nanshan/` |
| 单个风格原型文件 | `s<NN>-<style-slug>.html`（s=style，NN 为 01–10 序号，slug 为风格英文短横线名） | `s03-organic-biophilic.html` |
| 主题评审墙 | 每主题目录内固定名 `review-wall.html` | `e02-nanshan/review-wall.html` |
| 总入口 | 命名空间根下 `index.html` | `prototypes/qoder/index.html` |
| 台账状态位 | 本文档进度表（第 7 节），文件命名不再重复状态 | — |

**命名硬规则**：
1. 文件名全小写、短横线连接，禁止空格与中文文件名（避免部署与 Git 跨平台问题）。
2. 风格序号 `s01…s10` 在本主题内唯一，且与本文档选型表**一一对应**，改风格须同步改表。
3. 任何人新增产出，请另建自己的 `prototypes/<你的名字>/`，**不要写入 `qoder/`**，从根上避免重复与冲突。

### 2.2 目标目录结构

```
prototypes/qoder/
├── index.html                 ← 总入口：3 主题入口卡片
├── e02-nanshan/               ← 主题一 · 鹏城数字名片（南山）★主推
│   ├── review-wall.html
│   └── s01…s10-*.html
├── e03-pedia/                 ← 主题二 · 亚太经济体互动百科
│   ├── review-wall.html
│   └── s01…s10-*.html
└── e01-summit/                ← 主题三 · APEC 2026 深圳峰会主题网站
    ├── review-wall.html
    └── s01…s10-*.html
```

### 2.3 原型技术约定

- **单文件自包含**：每个原型 HTML 内联 CSS/JS，双击即可在浏览器打开，不依赖构建、不依赖网络字体（用系统字体栈）。
- 每个原型至少呈现：该入口的 **Hero 首屏 + 1 个核心内容带（band）+ 1 处南山元素 + 资料来源标注位**。
- 尺寸基线：桌面容器 `max-width` 合理收敛，移动断点 `≤640px` 单列化。
